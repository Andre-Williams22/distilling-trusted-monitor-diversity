# distilling-trusted-monitor-diversity

Can inference-time monitor diversity be distilled into a single trusted monitor
— recovering most of a 3-monitor ensemble's backdoor-detection gain at 1x
inference cost, using no labels and no stronger teacher?

Two distillation methods compared side by side: DPO on MACA-style
consensus-derived preference pairs, and supervised distillation from the
ensemble's mean scores. Evaluated as static classification on the
[ControlArena APPS backdoor dataset](https://huggingface.co/datasets/RoganInglis/apps-control-arena).

See `project-plan.md` for the full design, `CONTEXT.md` for vocabulary, and
`docs/adr/` for the decisions and their trade-offs.

## Environment

**Use `.venv` (uv-managed). Delete any hand-made `venv/`.** Two virtualenvs in
one repo is a reliable way to spend an afternoon debugging an import error —
`uv` owns `.venv` and will recreate it from the lockfile whenever it needs to.

```bash
rm -rf venv                       # the hand-made one, if present
```

`uv.lock` is the **source of truth**: it pins every transitive dependency for
every platform, so the laptop and the GPU box resolve to the same versions. It
is committed. The files in `requirements/` are *exports* of it, regenerated by
command, for anywhere `uv` is not available.

### Three dependency tiers

The laptop is arm64 with no CUDA, so `vllm`, `torch` and `bitsandbytes` cannot
install there at all. A single dependency list would fail `uv sync` on day one,
so the tiers are separate.

| Tier | Install | Runs where | For |
|---|---|---|---|
| `data` | `uv sync --extra data --extra dev` | anywhere | splits, metrics, stats, tests |
| `local` | `uv sync --extra data --extra local` | Apple Silicon | 4-bit pilot scoring via MLX |
| `gpu` | `uv sync --extra gpu` | CUDA box | vLLM serving, QLoRA training |

`control-arena` is deliberately **not** a dependency — only its dataset is used.
See [ADR-0004](docs/adr/0004-static-classification-not-a-live-control-protocol.md).

### Setup — laptop

```bash
uv sync --extra data --extra dev      # creates .venv, installs from uv.lock
uv run pytest -q                      # 47 passed, 9 skipped
uv run python main.py build-data      # writes data/splits/
```

`uv run` executes inside `.venv` without activating anything. Activate only if
you prefer it:

```bash
source .venv/bin/activate
```

### Setup — local pilot (Apple Silicon)

```bash
uv sync --extra data --extra local
uv run python main.py score --arm m0 --split val --backend mlx --limit 100
```

First run downloads ~4.5 GB of 4-bit weights. **These scores are not comparable
to bf16 served scores** — the pilot answers "does my prompt work and is the
model above chance", not "what is the gate number".

### Setup — GPU box

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
git clone <this repo> && cd distilling-trusted-monitor-diversity
uv sync --extra gpu
uv run vllm serve Qwen/Qwen2.5-7B-Instruct \
  --gpu-memory-utilization 0.85 --max-model-len 8192
# then, in a second shell:
uv run python main.py score --arm m0 --split test
```

## uv commands

| Task | Command |
|---|---|
| Install a tier | `uv sync --extra data --extra dev` |
| Run anything in the env | `uv run python main.py --help` |
| Run tests | `uv run pytest -q` |
| Add a runtime dependency | `uv add <package>` |
| Add to a specific tier | `uv add --optional gpu <package>` |
| Remove one | `uv remove <package>` |
| Refresh the lock after editing `pyproject.toml` | `uv lock` |
| Upgrade everything within declared bounds | `uv lock --upgrade` |
| Upgrade one package | `uv lock --upgrade-package transformers` |
| Install exactly the lock, no resolution | `uv sync --frozen` |
| Show the resolved tree | `uv tree` |

### Regenerating `requirements/`

These are derived artifacts — edit `pyproject.toml` and re-export, never edit
them by hand.

```bash
uv export --format requirements-txt --no-hashes --no-emit-project \
  --extra data --extra dev  -o requirements/laptop.txt
uv export --format requirements-txt --no-hashes --no-emit-project \
  --extra data --extra local -o requirements/pilot.txt
uv export --format requirements-txt --no-hashes --no-emit-project \
  --extra gpu -o requirements/gpu.txt
```

Then, on a machine without uv:

```bash
python -m venv .venv && .venv/bin/pip install -r requirements/gpu.txt
```

## Pipeline

Every stage is independently runnable and resumable — generation jobs run for
hours on interruptible instances and append each result as it completes.

```bash
uv run python main.py build-data                        # splits (no GPU)
uv run python main.py score --arm m0 --split val        # the 14 Sep gate
uv run python main.py score --arm m1 --split test
uv run python main.py score --arm m2 --split test
uv run python main.py diversity-check --split val       # ADR-0002
uv run python main.py teacher-scores --split train      # M4's targets
uv run python main.py debate --split train              # M3's transcripts
uv run python main.py build-pairs
uv run python main.py train-sft                         # M4
uv run python main.py train-dpo                         # M3
uv run python main.py analyse
```

`main.py --help` lists every stage.

## Artifacts

| Directory | Git | Holds |
|---|---|---|
| `data/` | ignored | splits, raw generations, derived training files |
| `runs/` | ignored | one dir per run: `DATE__arm__githash/` with adapter, logs, config |
| `results/` | **committed** | scores tables, `hypotheses.csv`, figures |

`results/` is committed on purpose: it is a few hundred KB and it is what the
write-up cites, so every reported number stays timestamped and attributable to
a commit.
